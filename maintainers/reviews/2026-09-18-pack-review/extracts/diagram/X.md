**Trigger:** Loads on-demand, matched against a 228-word frontmatter description listing phrases such as "diagram this," "make an architecture diagram," "visualize this system/flow/pipeline," or any request to lay out a system's components and the paths between them. It is not always-on; it activates only when the request matches that intent, and the description also states cases it should not fire for (slide decks, static one-pagers, numeric chart data, deck-structure planning).

**What it makes the agent do:** An eight-step build workflow: Step 0 requires pinning down components, groupings, connections, and 2-5 named flows in plain text first, and to "reflect back" that list and confirm with the user before drawing if the description is loose. Step 1 requires copying the bundled template file with a file operation and editing only the four content slots in place, explicitly forbidding regenerating the whole file in one pass, because doing so risks truncating the frozen style/script engine mid-output. Steps 2-6 fill in zones, nodes, edges/labels, a per-node detail object, and a per-flow highlight object, each governed by a separate reference file. Step 7 is framed as mandatory and non-negotiable: "a diagram is not finished until scripts/validate.py has been run on it and exits clean," to be run with a flag that also produces light/dark/flow screenshots to be opened and visually checked for overlapping or colliding elements. Step 8 only becomes reachable once the validator exits clean, at which point the finished file is copied to an output location, presented, and the user is told plainly that the validator passed along with a disclosure of which architectural judgment calls were inferred.

**Enforcement:** scripts/validate.py is the enforcement mechanism. It first runs a structural-integrity check (file ends with the closing HTML tag, script tags balanced, named "engine sentinels" present) independent of cross-reference logic, specifically to catch a file that looks complete but was cut off mid-write; on any structural problem it prints FAIL lines and exits non-zero before even attempting cross-reference checks. It then cross-checks that every flow-referenced edge and node id exists in the diagram, every node has a matching detail entry, and every edge label points at a real edge, printing FAIL lines and warnings and exiting non-zero on any mismatch, or printing "pass" and exiting 0 if everything resolves. It fails closed on both checks — a non-zero exit is the intended gate, and the skill text instructs not to proceed past that step on any failure. The optional screenshot pass depends on a browser-automation library that is not bundled; if that library cannot be imported, the script prints a message and skips screenshots rather than failing, so the visual-inspection portion of the gate is not itself mechanically enforced.

**Dependencies:** python3 to run the validator; a browser to view the resulting HTML file; the optional screenshot step additionally needs a browser-automation library that is not bundled and must be fetched separately if absent, per the skill's own instructions for obtaining it. A packaging step referenced at the end of the file also invokes a separate script module to produce a distributable file, implying a broader toolset the skill assumes exists alongside it. (Counted facts also list node as a runtime dependency, though it is not otherwise visible in the reviewed files.)

**State it writes:** A working copy of the template HTML file is created on disk and edited in place; the finished file is later copied to an output directory before being presented. The optional screenshot step writes separate light-mode, dark-mode, and active-flow image files alongside the working file. No other logs or persistent state are described.
