# Content checklist (criterion-separated)

This is the rubric side of site-review: the part Lighthouse and linkinator
cannot score. Each row is scored independently, PASS or FAIL, never rolled up
into one number. A site can pass every row here and still fail the /goal
condition on scores or links, and vice versa; the two are separate success
criteria (roadmap entry, "Success").

Score every row against the live, rendered site (not the source), at both
the default viewport and the 375px / dark-theme pass named in `## Verify`.

| # | Criterion | How to check |
|---|---|---|
| 1 | `<title>` is present and describes the page, not the framework default | View source or `curl -s <url> \| grep -o '<title>[^<]*</title>'` |
| 2 | Meta description present and under ~160 characters | Same, for `<meta name="description">` |
| 3 | Favicon loads (no broken favicon request in the network panel) | Screenshot + network tab, or `curl -sI <url>/favicon.ico` |
| 4 | Open Graph title/description/image present for the homepage | `curl -s <url> \| grep -o '<meta property="og:[^>]*>'` |
| 5 | No placeholder or lorem-ipsum text visible anywhere on the crawled pages | Screenshot review; `grep -ri 'lorem ipsum'` on rendered HTML |
| 6 | No broken images (img tags that 404 or render as a broken-image icon) | Screenshot review at both viewports |
| 7 | Primary navigation is usable at 375px width (no overlapping or cut-off items) | 375px screenshot, `## Verify` |
| 8 | Text and interactive elements are legible in dark theme (no white-on-white or black-on-black) | Dark-theme screenshot, `## Verify` |
| 9 | Footer copyright year is the current year or later | Screenshot or rendered HTML |
| 10 | `robots.txt` and `sitemap.xml` both resolve (200, not a soft-404 page) | `curl -sI <url>/robots.txt`, `curl -sI <url>/sitemap.xml` |
| 11 | A custom 404 page exists (not the platform's generic error page) | `curl -s <url>/definitely-not-a-real-path-xyz` |
| 12 | Contact or key business information on the page matches what the site owner confirms is current | Ask the site owner for the current values; do not assume |

## Adding criteria for a specific site

The roadmap's Inputs line names "optional content checklist additions." Append
rows to a copy of this table for the specific review; do not edit this file
per-review (it is the shared reference, one editable home). Number new rows
continuing from 13 so a review's report can cite "row 13" unambiguously.

## Known weakness

This checklist is a floor, not a design review. It catches missing or broken
things a script or a glance can verify; it says nothing about whether the
design is good, the copy is persuasive, or the information architecture makes
sense. Rows 5, 6, 7, 8 are visual judgment calls made by whoever runs the
review (a human, or the reviewer subagent under `review-pair`'s independent
re-score); they are not automatable the way rows 1, 2, 4, 9, 10, 11 are. Do
not report "checklist complete" as equivalent to "the site looks good" — it
means every row above was checked and passed, nothing more.
