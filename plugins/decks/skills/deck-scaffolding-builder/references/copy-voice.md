# Copy Voice

**If the project has a dedicated voice/tone skill, the universal voice rules - tone, contractions, punctuation, and the full banned-AI-tells word list - should live there. Load it for any customer-facing copy and use it as the source of truth.** If no such skill exists, use the plain, direct default described below and the banned-tells list at the bottom of this file. This file adds only the deck-specific copy patterns on top of whichever voice source applies, so the two don't drift out of sync.

## Headlines are claims, not topics

A headline makes a point the buyer can agree or disagree with. A topic just names a subject.

- Topic (weak): "Cloud Cost Optimization"
- Claim (strong): "Waste that isn't found doesn't get fixed"

The accent-colored word carries the point ("You can see the bill." / "six pillars" / "Right now."). Short, declarative, often two lines, second line sometimes in a lighter tone.

## Pattern-recognition framing (the highest-value pattern in the deck)

The most persuasive slides describe the buyer's situation back to them so accurately they self-identify before any capability claim. This is the copy that carries the deck - and the part the skill should never fake. If the specific situation isn't known, leave a `[NEEDS YOUR INPUT]` marker rather than inventing a generic version.

- Don't say "we help with migrations." Describe the migration that went sideways: "The timeline was set before the application inventory was done. The scope expanded. The original estimate didn't."
- Name archetypes. The reference deck uses three named customer scenarios per section (e.g. The Overcommit, The Invisible Levers, The Coverage Gap Nobody Caught), each with a two-sentence recognition description. The buyer reads one and thinks "that's us."
- Lead with what we find, not what good looks like. "Account sprawl with no ownership model is one of the most common things we find" beats "we build well-structured accounts."

## Eyebrows

Name the section/theme in 1-4 words, all caps, accent color. They orient, they don't explain.

## Body copy

Plain and short. No filler. One idea per slide - the layout never competes with the point. Footnotes carry the caveat or the "why this matters" closer in muted italic.

## Density by slide position

Front of a section = punchy headline slides, presenter carries, minimal copy. Back of a section = self-service depth slides where more copy is appropriate because they're built to be read without a presenter. Match the copy-density field in the schema to the slide's position.

## Quick reminder of the worst tells

(Full list, if the project has a dedicated voice skill, lives there.) The ones that creep into deck copy most: delve, crucial, pivotal, landscape (as abstract noun), showcases, underscores, "serves as," "represents a," "not just X but also Y," and the rule of three used as a stylistic crutch. Also mannered prose, where a metaphor stands in for a plain statement ("a dial worth turning" for "a parameter worth varying"): say the literal thing. Hyphens not em dashes, straight quotes not curly.
