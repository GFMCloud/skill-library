### Steelman Y

item-ed2aee87 is a lean, purpose-built checklist skill that does exactly what the bar demands with almost no baggage. It loads on demand from a small, explicit trigger list, covers ten named security areas with a search-before-PASS discipline, and forces every finding to carry file/line/quoted-code/severity plus the checklist row it fails. Its stop-gate design directly encodes the "plan, then stop" behavior at the point of highest risk: it categorically bars the agent from ever touching credentials or account settings, routes every other state-changing step through a "Proposed actions" list requiring per-action confirmation, and treats a suspected live secret as a hard halt. It has zero runtime dependencies, writes no state of its own, and its output template ends in a mandatory "Not checked" line — a direct, cheap satisfaction of the third bar behavior. It is also honest about its ceiling: no logic-flaw detection, no automated scanning, and cloud/account rows are expected to land on NOT VERIFIABLE rather than being rubber-stamped.

### Steelman X

item-fd563265 is a far more rigorous system that backs its prose with actual executable checks. Two Node validator scripts (with their own test suites) mechanically enforce the structure and semantics of the findings and coverage artifacts — fail-closed, capped error output, exit code discipline — which is a real tool-layer gate, not just an instruction. The workflow's design is unusually attentive to the exact failure modes the bar cares about: an independent verifier must try to refute every candidate finding from source before it counts, a second independent verifier gates the final report, sandboxed execution is required with a named list of controls (no network, empty env, resource caps) and an explicit instruction to abstain (`needs_validation`) rather than run unsafely if any control is missing. Guidance mode is the default and explicitly withholds file creation and the full workflow unless the request is unambiguous, and a one-question clarifier is mandated when it's ambiguous — a strong, concrete instance of "plan, then stop." The checklist library is domain-specific and opinionated about what does *not* count as a finding ("prompt injection alone is not a finding," "a missing rate limit is not enough"), which is exactly the kind of concrete failure-mode guidance the bar rewards.
