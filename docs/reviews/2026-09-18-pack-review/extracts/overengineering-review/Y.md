### For each item

**item-c3affd53**
**Trigger:** Loads on-demand when the user names it or asks to review a diff/PR with multiple reviewers, or when it is invoked as the review phase of a separate pipeline skill it names in its own description. Not always on.
**What it makes the agent do:** Validate the input argument first ("Never pass the raw argument to a shell," extract only a bare integer or a PR-URL's trailing integer, else stop). Gather the diff (local git diff, or `gh pr diff`/`gh pr view`), stop on an empty diff, drop binary/generated files. Fan out one read-only subagent per dimension — correctness/maintainability, a silent-failure check, and a security check gated on whether the file list touches a security-relevant area — each seeing only the diff and file list, no conversation history. Require every finding to carry file, line, severity, and quoted code. Deduplicate on the quoted code (whitespace-normalized), keeping the highest severity. Send every unique critical/high finding to a fresh subagent that tries to refute it. Report a fixed-shape output with verdict, dimension count, a reconciling stats line, blocking/advisory findings with evidence, and an explicit "not checked" line.
**Enforcement:** Prose only; no script or other executable checks it. Compliance with the fail-closed rule ("If any dimension errored, timed out, hit a rate limit, or could not be spawned, the result is `incomplete`... not `APPROVE`") and the stats-arithmetic check ("raw = unique + duplicates") depends on the agent following the written procedure; nothing in the files enforces it mechanically. It states it fails closed on dimension failure, but nothing external verifies that the agent actually did so.
**Dependencies:** git; a PR-hosting CLI (`gh`) for PR mode; the ability to spawn multiple subagents; two named external checklists/agents from another plugin bundle for the silent-failure and security dimensions. No named runtime dependency beyond that, matching the facts table's "none named."
**State it writes:** None. It states outright: "This skill commits nothing and approves nothing on its own." The report is presented, not saved.
**Fit with the bar:**
- Plan then stop before consequential work: supported indirectly — it never modifies anything itself, and it stops rather than substituting a "hand-rolled review" when a dimension fails: "Do not fall back to a hand-rolled review and do not imply the diff was approved."
- Executed evidence before "done": partially supported — every finding must quote code that exists at the cited line, but reviewers only read, they don't run anything; a finding needing execution to confirm is explicitly left as "could-not-verify" rather than resolved by evidence.
- Say what was and was not checked: directly supported — the output contract has a mandatory "not checked" line and a dimension-ran/failed count.
No conflicting lines found.
**What it does not cover:** States its own limit plainly: "reviewers read, they do not execute. A finding that needs a test run to confirm stays in blocking as could-not-verify, which is noisy by design." It also does not apply or fix anything ("read-only, it fixes nothing") and has no mechanism to verify its own stats-line arithmetic beyond telling the reader what "pass" means.

**item-e739493a**
**Trigger:** Loads on-demand when a change spec or diff is about to be applied to "a real file, a real deploy, or anything where a wrong apply costs a rework cycle," typically after a bounded/goal-driven build step. Not always on.
**What it makes the agent do:** Confirm a goal block and a change spec are both in hand, else stop and ask for the missing field. Spawn a reviewer subagent configured read-only (plan permission mode, a disallowed-tools list barring writes/edits, a turn cap, and a model that must differ from the builder's), giving it only the goal block and the change — never the builder's transcript or reasoning — plus a discipline reference document when the change is code. Take the reviewer's returned Verdict object and write it to a run log before anything else happens with it. Run the validation script on it. On a passing, valid verdict, apply the change and stop seeking further opinions. On a failing verdict, give the builder one bounded retry, get a second verdict marked for whether it cites new information, and run the script on both verdicts together. If the script signals a repeat fail, stop, do not apply, and escalate the target to a named individual for a ruling rather than retrying a third time.
**Enforcement:** `scripts/verdict-check.sh`, an executable. It checks required fields are present, `result` is `pass`/`fail`, `severity` and `confidence` are in their allowed ranges, `issues` is empty exactly when the result is a pass, and every issue's evidence names an executed check and its output or an explicit not-checked marker — rejecting a bare quote (proven by a dedicated fixture). Exit codes: 0 valid, 1 malformed/invalid (blocks — "the apply does not proceed on it either way"), 2 valid-but-repeat-fail (blocks and triggers the hold/escalation path). It fails closed: a script failure or malformed output is treated as not a pass, never a default approval.
**Dependencies:** bash (for the script); a subagent-spawn mechanism with configurable permission mode/tool allowlist/model; a model for the reviewer that differs from the builder's model; an external interface-spec document defining the exact Verdict and goal-block field lists (the skill's own files defer to it rather than duplicating it); a separate skill supplying the retry-budget rule; an agent-definition file meant to be copied into a project's own agent directory.
**State it writes:** The reviewer's Verdict object is written to "the run log" before the apply proceeds (no concrete path given in the files). The fixtures directory holds static test verdicts, not runtime output.
**Fit with the bar:**
- Plan then stop before consequential work: strongly supported — multiple explicit stop conditions gate the apply (missing goal block, unparseable verdict, no differing reviewer model, repeat fail), and "Nothing runs until every field except `rubric` is filled."
- Executed evidence before "done": strongly supported — the evidence field must be an executed check and its output, and the validator mechanically rejects a bare quote: "A quote from the change is not evidence on its own; `scripts/verdict-check.sh` rejects it."
- Say what was and was not checked: supported — a `not-checked: <reason>` marker is an accepted, valid form of evidence, and the files state plainly what the validator cannot itself confirm (see below).
No conflicting lines found.
**What it does not cover:** States its own limit directly: "the script validates shape, the evidence field's form and the hold rule. It cannot check that the command an issue cites was really run or that its quoted output is real" — that gap is left to the reviewer's restricted permissions and model independence rather than to any check. It also treats style/idiom as out of scope unless a named constraint calls for it, and the reference list of "usually false" findings is noted as unverified in this setting: "the list comes from one source project's experience and has not been measured here."
